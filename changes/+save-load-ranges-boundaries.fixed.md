Saving and loading a configuration no longer changes its results. A `binarize_mask` range `mask_values: (lo, hi)` was saved as a list. A list selects only the listed labels, so a range such as `(1, 3)` lost label 2 after loading. A range is now saved as `{range: [lo, hi]}` and loads back as the tuple. You can also write this form in YAML and JSON files, which cannot hold tuples. A `BoundaryCondition` member was saved as its scipy mode name, for example `"reflect"`. Loading rejects that name, so the reloaded filter step failed. The member is now saved by its name, for example `"mirror"`. These two values also no longer break `describe_features()` or a deduplicated run with more than one configuration. A range and a label list with the same numbers no longer share deduplicated results.
