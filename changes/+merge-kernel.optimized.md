`load_and_merge_images` merges each image in one parallel pass (a compiled kernel for float64, uint8, int16 and uint16 arrays in row order from 2^18 voxels) instead of four numpy passes with bool arrays of the image size. With `reposition_to_reference` and a fill value of 0, the merge starts as an array of zeros that the system gives on first use. On a 512x512x200 CT, the merge of 20 sphere masks takes about 0.54 s instead of 1.41 s, with a peak of 850 MB instead of 950 MB; the merge of 20 cropped masks into the reference takes about 20 ms instead of 29 ms. Results are unchanged, bit for bit, with one exception on x86-64: for a voxel with +0 in one image and -0 in the other, the max rule now gives +0 and the min rule -0, as on arm64 (numpy on x86-64 gave the zero of the later image, the same value).
