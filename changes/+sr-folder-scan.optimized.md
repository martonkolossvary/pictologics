`SRDocument.from_folders` finds the SR files by reading each file only up to its SOP Class UID, and parses SR files of less than 2.5 MB in total in the calling process (`SR_POOL_BYTES`) instead of starting `cpu_count - 1` worker processes, which each import Pictologics first (about 1 s). From 2.5 MB it starts the requested workers, as before. A folder of 200 small reports takes 0.53 s instead of 1.67 s, and the same reports among 6,000 CT files 1.12 s instead of 2.42 s. A file that breaks after its SOP Class UID now shows as an error in the processing log instead of being skipped.
